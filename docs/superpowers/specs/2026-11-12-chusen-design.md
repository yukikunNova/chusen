# 発表順抽選アプリ「ドパ抽」設計書

- 作成日: 2026-11-12
- 状態: レビュー待ち
- 凡例: 【決定】= 依頼者が決めたこと ／ 【判断】= 設計者の判断（依頼者は未確認または概要のみ了承）

## 1. 目的と背景

会議での発表順をランダムに決めるブラウザアプリ。機能は単純だが、**たかが発表順に対して過剰にド派手な演出**を行い、順番が決まる瞬間に場の笑いを取ることが最大の価値。

利用状況【決定】:

- 参加者は 5〜15 人。ふだんは 5 人前後
- オンライン会議の画面共有、または会議室のプロジェクターで映す
- 操作するのは 1 人（毎回同じ人が自分の PC で回す）
- 複数の集まり（チーム別・会議別）で名簿を使い分ける
- その回だけ不在の人がいるので、参加をオンオフしたい
- 抽選開始から全員の順番が出そろうまで 30 秒以内。短いほうがよい

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

1. 名簿（グループとメンバー）を保存し、次回そのまま再利用できる
2. メンバーごとに参加オンオフを切り替えられる
3. 3D のレース演出で発表順を発表し、笑いが起きる
4. 人数によらず 30 秒以内に全順位が確定する
5. URL を開くだけで使える（インストール・コマンド実行不要）
6. 結果を会議チャットに貼れる

### 非ゴール

- サーバー保存、アカウント、複数 PC 間の自動同期
- 抽選履歴の保存、当選確率の重み付け、「前回 1 番だった人を避ける」等の調整
- スマートフォン向け最適化（崩れない程度でよい）
- 多言語対応（UI は日本語のみ）
- 複数人が同時に操作する仕組み

### アンチゴール（技術的に動いても失敗とみなす）

- 全順位確定まで 30 秒を超える
- 演出をスキップできない
- 演出（物理計算や描画の遅れ）によって結果が変わる、または偏る
- 画面共有（低フレームレート・圧縮・音声なし）で誰が何番か読み取れない
- 名簿が意図せず消える
- 毎回まったく同じ展開で 3 回目には飽きる

## 3. 画面構成

画面は 3 つ。ページ遷移はせず、1 ページ内で切り替える【判断】。

```
名簿画面 ──[抽選スタート]──▶ レース画面 ──(ゴール or スキップ)──▶ 結果画面
   ▲                                                              │
   └──────────────[名簿に戻る]────────────────────────────────────┘
                                   結果画面 ──[もう一度抽選]──▶ レース画面
```

背景には常に 3D の宇宙空間を描画し、名簿画面と結果画面はその上に HTML の UI を重ねる【判断】。

### 3.1 名簿画面

起動時に表示。操作性を優先したふつうのフォーム【判断】。

- **グループ切替**: 複数グループを作成・名前変更・削除。上部のタブで切替（多い場合は横スクロール）
  - 削除は確認ダイアログあり
  - 最後に開いたグループを次回起動時に自動で開く
  - 初回起動時は空のグループ「グループ1」を 1 つ用意
- **メンバー一覧**: 選択中グループのメンバーを表示
  - 追加: 入力欄に名前を入れて Enter。改行区切りのテキストを貼り付けると複数人まとめて追加
  - 名前変更、削除（1 人ずつ）
  - 各メンバーに参加オンオフのスイッチ。オフは薄く表示し抽選対象外
  - 「全員オン」ボタン
  - 参加人数表示（例: `参加 5 / 7人`）
- **抽選スタート**: 大きなボタン。参加オンが 2 人未満なら無効
- **その他**: 音のミュート切替、名簿の JSON 書き出し・読み込み

制約【判断】:

- 名前は 1〜20 文字。前後の空白は除去。空は不可。重複は許可
- 1 グループ最大 30 人登録可。**抽選に参加できるのは最大 20 人**（超過時はスタートボタン無効＋理由表示）。演出は 15 人までを快適域として調整
- オンオフ状態は保存され、次回も前回のまま（自動リセットしない）

### 3.2 レース画面（ドパ抽）

参加オンの全員が名前入りロケットで宇宙コースを走り、**ゴール順 = 発表順**【決定】。ゴール時に花火を打ち上げる【決定】。

タイムライン（人数によらず固定、合計約 27 秒）【判断】:

| 時刻 | フェーズ | 内容 |
|---|---|---|
| 0–3s | 整列 | ロケットがスタートラインに並ぶ。カメラが列をなめる。3・2・1 カウントダウン |
| 3–19s | レース | コース爆走。追走カメラ・俯瞰カメラを切替。実況テロップと現在順位表を表示 |
| 19–23s | 最終コーナー | スローモーション。大逆転イベント。実況が最高潮 |
| 23–26s | ゴール | 約 2.5 秒の間に全員が順にゴール。1 位通過で花火開始、紙吹雪 |
| 26–27s | 遷移 | カメラが引き、結果画面へ |

画面要素:

- **3D**: 星空・星雲、ネオン調のコース（ゆるいカーブと起伏）、ロケット（色違い、噴射炎パーティクル）、ゴールゲート、花火、紙吹雪。発光（ブルーム）効果
- **名札**: 各ロケットの上に名前を常時表示（日本語そのまま）
- **実況テロップ**（画面下、大きな文字）: 名前入りの実況文。例「田中、謎の出遅れ！」「佐藤が来た！佐藤が来たァ！」
- **現在順位表**（画面端）: レース中の暫定順位。途中の順位は演出であり最終結果とは異なる
- **スキップ**: スペースキーまたは画面隅の「スキップ」ボタンで即座に結果画面へ

演出イベント【判断】: 出遅れ、ロケットスタート、ブースト、スピン、蛇行、謎の失速、ごぼう抜き、最終コーナーでの大逆転 など 8 種以上。実況文テンプレートは合計 30 本以上用意し、毎回ランダムに選んで展開を変える。

人数への対応【判断】:

- 全員が同時に走るため、人数が増えても尺は同じ
- レーンは横一列を基本とし、9 人以上は 2 段（上下）に配置
- 実況テロップは同時に 1 本だけ表示。人数が多い回も 1 レースあたり 8〜10 本（2 人のときは 7〜9 本）
- ゴールは 2.5 秒の窓に等間隔で収める（15 人なら約 0.17 秒間隔）

写真判定（第 3 弾で追加）【判断】:

- 2 人以上のレースで約 3 回に 1 回。台本用とは別の乱数で抽選するので、順位にもほかの機体の進み方にも影響しない
- 2 着のゴール時刻を 1 着の直後（0.05 秒以内）に寄せ、ゴール前後の 0.4 秒だけ時間の進みを 1/5 にする。この回はレース全体が約 1.6 秒長くなる
- スロー中は音楽を止めて心臓の音にし、ゴール線を横から望遠で撮る。「📸 写真判定」を出し、2 着がゴールしたら「0.00X秒差!!」を出す（数字は 0.001〜0.009 の飾り）
- 視差軽減の設定ではスローと望遠カットを使わず、表示だけ出す。簡易表示（3D なし）では写真判定にしない

### 3.3 結果画面

会議中そのまま映しておける静的な画面。

- 大きな順番表（`1 佐藤` `2 田中` …）。9 人以上は 2 列
- 1 番手は特大・金色で強調
- 背景で花火が打ち上がり続ける（数十秒後に頻度を落とす）
- ボタン: 「結果をコピー」（`1. 佐藤\n2. 田中…` 形式のテキストをクリップボードへ）、「もう一度抽選」、「名簿に戻る」

第 3 弾で追加（X などで共有するための要素）:

- **称号**: 名前の横に札で出す（ごぼう抜き王／ドパ値MVP／スナイパー／金だらい被害者／ガス欠の人／ねむけに負けた人／土壇場の追い上げ／ロケットスタート／出遅れの人／被弾王／鼻差の勝者／鼻差で泣いた人／大トリ）。台本から決まる飾りで、1 人 1 個まで、同じ称号は 1 人だけ
- **レースのまとめ**: コース名・ドパ値・写真判定の着差を 1 行で出す
- **結果カード画像**: 1200×675 の PNG を canvas で描く（順位・名前・称号、コース名、ドパ値、写真判定、`#ドパ抽`、公開先）。11 人目以降は「ほか N 人」。見本を結果画面に出す
- **共有のボタン**: 「画像を保存」「画像をコピー」「X に投稿」。X の投稿画面は画像を受け取れないため、「X に投稿」は画像をクリップボードへ入れてから投稿文入りの投稿画面を開き、貼り付けを案内する。コピーできない環境では保存して添付するよう案内する
- **名前を伏せる**: 「共有では名前を伏せる」を入れると、画像と投稿文の名前が「Aさん・Bさん…」になる（初期は実名）。画面上の順番表は実名のまま。伏せたときに実名が画像・投稿文・投稿先 URL に残らないことをテストで確かめる

## 4. 抽選の公平性【判断】

- 「抽選スタート」押下時に、参加オンのメンバーを **Fisher–Yates シャッフル**で並べ替えて最終順位を確定する
- 乱数は `crypto.getRandomValues` を使い、剰余の偏りが出ないよう棄却サンプリングで整数を得る
- レース演出は確定済みの順位を**再生するだけ**。物理シミュレーションで順位を決めない
- スキップしても、演出を最後まで見ても、結果は同じ
- 「もう一度抽選」は新しくシャッフルし直す

### 5.2 モジュール分割

ロジックと描画を分け、ロジックは純粋関数としてテスト可能にする。

```
src/
  main.ts                 起動、画面切替
  domain/
    shuffle.ts            公平シャッフル（乱数源を引数で受ける）
    roster.ts             グループ・メンバー操作（不変データの純粋関数）
    race-script.ts        最終順位 → レース台本を生成（写真判定を含む）
    commentary.ts         実況文テンプレートと選択
    summary.ts            レースのまとめ（称号・ドパ値など）の型
    share.ts              共有する中身（画像に描く内容、投稿文、伏せ字）
  storage/
    store.ts              localStorage 読み書き、スキーマ検証、書き出し・読み込み
  ui/
    roster-view.ts        名簿画面
    result-view.ts        結果画面（称号、共有のボタン）
    share-card.ts         結果カード画像を canvas に描く
    hud.ts                テロップ、順位表、カウントダウン、スキップ
  scene/
    stage.ts              レンダラー、カメラ、リサイズ、描画ループ
    space.ts              星空・星雲
    track.ts              コース、ゴールゲート
    rockets.ts            ロケットと名札
    fireworks.ts          花火、紙吹雪
    race-player.ts        台本を時刻に沿って再生
    race-clock.ts         レースの時計、スロー区間の時間の伸縮
    titles.ts             台本から称号とレースのまとめを決める
  audio/
    sfx.ts                効果音合成、ミュート
```

### 5.3 レース台本（`race-script.ts`）

演出の核。確定した最終順位から、時刻に対する全ロケットの動きを**事前に全部決める**。

- 入力: 最終順位（メンバー ID の配列）、演出用乱数源
- 出力:
  - 各ロケットの進行度キーフレーム（時刻 → コース上の位置 0〜1）
  - 各ロケットのゴール時刻
  - イベント列（時刻、種類、対象ロケット）
  - 実況キュー（時刻、文）
- 守るべき性質（テストで保証）:
  1. ゴール時刻の昇順が最終順位と完全に一致する
  2. 全員のゴール時刻が 23〜26 秒の窓に収まる
  3. 各ロケットの進行度は時刻に対して単調非減少（後退しない）
  4. 参加 3 人以上なら、レース中のどこかで暫定順位が最終順位と異なる（逆転が起きる）
  5. 同じ入力と同じ乱数種なら同じ台本になる
- 再生側（`race-player.ts`）は経過時刻から位置を補間して描くだけ。フレームレートが落ちても結果と尺は変わらない（実時間基準）

演出用の乱数は公平性に関係しないので、種付きの擬似乱数でよい。

#### 攻撃アイテム（2026-11-12 追加・利用者の要望）

- 中盤イベントの一種として、ある機体が別の機体にアイテムを当てる。2 人以上なら毎レース最低 1 回起こる
- アイテムは本アプリ独自の 3 種【判断】: 仕様変更ミサイル（一直線）、長文メール爆弾（山なり）、差し戻しサンダー（上空から）
- 被弾機はスピンして一時的に遅れる。弾は着弾の 0.9 秒前に飛び始め、着弾で爆発する。実況は攻撃者・アイテム・被弾者の名前を入れる
- **順位には影響しない。** 結果は開始時に確定済みで、攻撃は台本上の演出にすぎない（上の性質 1〜5 はそのまま成り立つ）

#### 乗り物の種類（2026-11-12 追加・利用者の要望）

- 乗り物は 16 種類。宇宙もの 7 種（ロケット・UFO・スペースシャトル・人工衛星・彗星・土星・月面車）、会議室の物 5 種（オフィスチェア・段ボール箱・コーヒーカップ・キーボード・ノート PC）、ネタ枠 4 種（アヒル・寿司・ドーナツ・便器）【判断】
- 誰がどれに乗るかは抽選のたびにランダム。16 人以下なら全員ちがう乗り物、17 人以上はどの種類も同じくらい使う
- 見た目だけの割り当てで、順位には関係しない。乗り物から結果は読めない
- 機体ごとの色は、乗り物の一部（本体・テープ・スリーブ・キーなど）に付けて見分けられるようにする

#### ランダムコース（2026-11-12 追加・利用者の要望）

- コースは抽選スタートのたびに作り直す。見た目だけで、順位には関係しない。所要時間は変わらない
- 区間をランダムにつなぐ: 直線・左右カーブ・上り下り・きりもみ回転（コースが軸まわりに 1 回転）・ジャンプ台（床が途切れ、機体が浮く）
- スタート直後とゴール手前は水平な直線。どのコースにもカーブがあり、きりもみかジャンプ台が 1 つ以上入る。きりもみは 1 コース 1 回まで
- 進行方向は正面から約 34 度以内に抑える（必ず奥へ進み、コース同士が重ならない）【判断】
- 縦の宙返りは入れない。必要な半径が大きくコースの 3 分の 1 以上を占め、カメラが破綻しやすいため【判断】
- テーマは 5 種から抽選: ネオン宇宙・溶岩・氷・お菓子・オーロラ。床・レール・リング・背景と霧の色・沿道の飾りが変わる
- カウントダウン中に「本日のコース: ○○」を表示する。呼び名はテーマと目立つ区間から作る（例: マグマきりもみ街道）
- カメラの上向きはコースの傾きに合わせる。OS の視差軽減設定時は画面を回さない
- 名簿画面の背景は直前のコース（初回は起動時に作ったコース）。結果画面の花火は同じコースのゴールで上げる

#### 途中経過の盛り上げ（2026-11-12 追加・利用者の要望）

すべて台本から開始時に 1 回だけ計算する見た目の演出で、順位には関係しない。

- 逆転ラッシュ: 進行度の節目を 2 秒刻みにして順位の入れ替わりを増やし、終盤（21 秒）にも揺らす。4 人以上なら「最下位から 2 秒で 3 人以上を抜くごぼう抜き」を必ず 1 回入れる。1 秒で 2 人以上抜いたら「○○ 3人抜き!!」の告知・閃光・効果音。告知は暫定順位を出した 1 秒後から、1.5 秒以上の間隔で出す
- コンボと点数: 見せ場（加速・命中・追い抜き・ごぼう抜き）が 3 秒以内に続くとコンボが増える。点数は基本点 × コンボ、フィーバー中は 10 倍。「ドパ値」として累計を表示し、機体の位置から「+1,500」が飛ぶ。点数は飾り
- アイテム箱: 既存の加速・攻撃・スピンなどの直前に、箱を取る → ルーレット → 結果、の前振りを付ける（1 レース 3 個まで）。結果は元のイベントと必ず一致する。白（ハズレ: 金だらい など）・金（ターボ・攻撃アイテム）・虹（ごぼう抜きの超ターボ）
- フィーバータイム: 最終コーナー（19 秒）から 1 着ゴールまで。「FEVER TIME!!」の告知、虹色の縁、集中線、広い画角、速いテンポの BGM
- OS の視差軽減設定時は、閃光・集中線・虹色の点滅・画面揺れ・画角の変化を出さない
- 閃光は 0.9 秒以上の間隔を空ける（重なって画面が白くなり続けないように）
- スキップ・終了時は HUD ごと消えるので、表示は残らない
- 流星群は入れていない【判断】

#### 花火の強化（2026-11-12 追加・利用者の要望）

- 1 着ゴールの瞬間と結果画面の表示時に、大玉 6 発を一斉に上げる。通常の打ち上げも約 3 割を大玉にする

### 5.4 名前の描画【判断】

名前は任意の日本語。3D の立体文字はフォントデータが巨大になるため使わない。

- ロケットの名札: Canvas 2D に文字を描いてテクスチャ化し、常にカメラを向く板（スプライト）として表示
- テロップ・順位表・結果表: HTML を 3D の上に重ねる
- 名札は長い名前を 8 文字程度で省略表示（テロップと結果表は全文）

### 5.5 保存データ

localStorage キー `chusen:v1`。

```ts
type Store = {
  version: 1;
  groups: Group[];
  lastGroupId: string | null;
  muted: boolean;
};
type Group = { id: string; name: string; members: Member[] };
type Member = { id: string; name: string; active: boolean };
```

- 変更のたびに即保存
- 読み込み時にスキーマ検証。壊れていたら、壊れたデータを別キー（`chusen:v1:broken`）に退避してから初期状態で起動し、画面に通知する
- 書き出し: `Store` をそのまま JSON ファイルとしてダウンロード
- 読み込み: 検証後、**現在の名簿を置き換える**（確認ダイアログあり）
- localStorage が使えない環境では、保存されない旨を表示してメモリ上だけで動作

### 5.6 音【判断】

- 効果音: カウントダウン、発進、ブースト、スピン、ゴール、花火、ファンファーレ。BGM はレース中の短いループ
- 初期状態は音あり。ミュート設定は保存
- ブラウザの自動再生制限は「抽選スタート」クリックを起点に音声を開始することで回避
- 音が聞こえなくても、すべての笑いどころは文字と絵で成立させる

### 5.7 表示と性能【判断】

- 基準は 16:9、1920×1080。ウィンドウサイズに追従
- 内蔵 GPU のノート PC で 60fps 目標。描画解像度倍率は最大 2、パーティクル数に上限
- 文字は太字・縁取り・高コントラスト。テロップは画面高の 6% 以上の文字サイズ
- WebGL が使えない場合: 3D なしで、順位を 1 行ずつ表示する簡易演出に切り替える
- OS の「視差効果を減らす」設定が有効なら、カメラの揺れと点滅を弱める

## 6. エラー処理

| 状況 | 挙動 |
|---|---|
| 参加 2 人未満 / 21 人以上 | スタートボタン無効、理由を表示 |
| 保存データ破損 | 退避して初期化、通知 |
| 読み込みファイルが不正 | 何も変更せず、エラー表示 |
| localStorage 不可 | 警告表示、メモリ動作 |
| WebGL 不可 | 簡易演出に切替 |
| クリップボード不可 | 結果テキストを選択状態で表示し手動コピーを促す |
| レース中にタブが非表示 | 実時間基準のため、戻った時点の時刻から再開（終わっていれば結果画面） |

## 7. テスト方針

- **単体テスト（TDD、Vitest）**: `shuffle`（乱数源を差し替えて決定的に検証、全順列が出ること）、`roster`、`race-script`（5.3 の性質 1〜5 を 2・3・5・15・20 人で検証）、`commentary`、`store`（検証、破損、書き出し・読み込み往復）
- **描画・音**: 自動テスト対象外。ブラウザで実際に動かして確認（5 人と 15 人、スキップ、もう一度抽選、リサイズ、ミュート）
- **通し確認**: ブラウザ自動操作で「メンバー追加 → オフ切替 → 抽選 → スキップ → 結果にオフの人がいない → 再読込で名簿が残る」を確認

- CSS の細部

## 9. 公開と運用

- 【決定】公開先は GitHub Pages、個人アカウントの**公開リポジトリ**。GitHub Actions でビルドして配置する
- 【決定】操作者のブラウザは Chrome / Edge。localStorage のみの保存で足りる（Safari の保存データ自動削除への対策は行わない。Safari でも動作はするが名簿の長期保持は保証しない）
- 【判断】このフォルダで `git init` する（ブランチは `main`）。`.superpowers/` は `.gitignore` に入れる
- 【判断】GitHub リポジトリの作成と push は外部への公開操作なので、実行前に依頼者へ確認する。リポジトリ名は `chusen` を想定（URL は `https://<アカウント>.github.io/chusen/`）
- 【判断】Vite の `base` は相対パス（`./`）にし、リポジトリ名が変わってもビルドが壊れないようにする
- 名簿は URL（オリジン）に紐づく。ローカル開発中（`localhost`）に入れた名簿は公開 URL からは見えないので、JSON 書き出し・読み込みで移す。公開 URL を後から変える場合も同じ手順

## 10. 作る順番と優先度【判断】

締切は指定なし。次の順に積み、各段階で動く状態を保つ。時間が足りなくなった場合は下から削る。

1. 名簿（グループ、メンバー、オンオフ、保存）＋シャッフル＋結果画面（演出なしで順番が出る）
2. レース台本と最小のレース演出（ロケット、名札、コース、ゴール、スキップ）
3. 実況テロップ、現在順位表、演出イベント、カメラワーク
4. 花火、紙吹雪、発光効果
5. 効果音
6. GitHub Pages 公開
7. JSON 書き出し・読み込み
8. BGM、WebGL 不可時の簡易演出、視差軽減対応
