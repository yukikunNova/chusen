# 発表順抽選アプリ「銀河グランプリ」Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 名簿を保存・再利用でき、参加オンオフを切り替え、3D ロケットレース演出で発表順を 30 秒以内に決めるブラウザアプリを作る。

**Architecture:** 結果は開始時に公平シャッフルで確定し、純粋関数が「レース台本」（全ロケットの時刻→位置）を生成、Three.js 側は実時間に沿って台本を再生するだけ。ロジック（`domain/` `storage/`）は DOM・Three.js に依存させず TDD、描画（`scene/`）と UI（`ui/`）は薄く保ちブラウザで目視確認する。画面は 1 ページ内で 名簿 → レース → 結果 を切り替え、3D キャンバスの上に HTML を重ねる。

**Tech Stack:** Vite 8 / TypeScript 7 / Three.js 0.187 / Vitest 5 + happy-dom / Prettier 3 / Web Audio API / GitHub Pages（GitHub Actions）

**Spec:** `docs/superpowers/specs/2026-11-12-chusen-design.md`（実装者は必ず併読）

## Global Constraints

- 依存は `three` のみ（実行時）。開発時は `vite` `typescript` `vitest` `happy-dom` `prettier` `@types/three`。UI フレームワーク・状態管理ライブラリ・音声/画像アセットは入れない
- 版は 2026-11-12 時点の最新（three 0.187.0 / vite 8.3.8 / vitest 5.1.0 / typescript 7.0.2 / prettier 3.10.0 / happy-dom 21.0.4）。**設定書式と import パスは記憶で書かず、context7 で公式ドキュメントを確認する**。最新版同士でツールが噛み合わない場合に限り、動く直近の版へ下げてよい（下げた版と理由をコミット本文に書く）
- `tsconfig`: `strict: true`、`noUncheckedIndexedAccess: true`。`any` 禁止
- Prettier: 2 スペース、シングルクォート、セミコロン、幅 100。各タスクのコミット前に `npm run format` → `npm run format:check`
- `domain/` と `storage/` は `three`・`document`・`window` を import / 参照しない（乱数源・ID 生成・Storage・時計は引数で受ける）
- Vite の `base` は `'./'`
- UI 文言はすべて日本語。利用者入力（名前・グループ名）は必ず `textContent` で描画し、`innerHTML` に入れない
- 保存キー `chusen:v1`、破損退避キー `chusen:v1:broken`
- 数値: 名前 1〜20 文字（コードポイント単位）、1 グループ最大 30 人、抽選参加 2〜20 人、レース全長 27 秒、ゴール窓 23.0〜25.5 秒
- レースの進行は実時間（`performance.now()`）基準。フレーム数で進めない
- 実況文は自作。実在の作品・実況者の決め台詞を引き写さない
- TDD: テストを先に書き失敗を確認 → 最小実装 → 整理。Green にする間テストを変更しない
- コミットは conventional commits（`feat:` `test:` `chore:` `docs:`）、説明は日本語。Co-Authored-By 等の帰属行は付けない
- `git push`・GitHub リポジトリ作成は Task 11 でユーザー確認後のみ

## Review Focus

仕様が暗に含むが見落としやすい入力・状況。各行のテストは括弧内のタスクに入れてある。

1. 名前に絵文字・サロゲートペア・HTML 断片（`<img src=x onerror=alert(1)>`）→ 文字数はコードポイントで数え、画面には文字としてそのまま表示される（Task 2・Task 4・Task 6）

4. レース中にタブ非表示・PC スリープ・ウィンドウリサイズ・全画面切替 → 戻った時点の実時刻から続行、27 秒を過ぎていれば即結果画面、描画は新サイズに追従（Task 6）

```ts
import { describe, expect, it } from 'vitest';
import { cryptoRandomInt, shuffle } from './shuffle';

describe('shuffle', () => {
  it('Fisher–Yates: 後ろから i を下げ j=randomInt(i+1) と交換する', () => {
    expect(shuffle(['a', 'b', 'c', 'd'], () => 0)).toEqual(['b', 'c', 'd', 'a']);
  });
  it('randomInt には i+1 を渡す', () => {
    const seen: number[] = [];
    shuffle([1, 2, 3, 4], (n) => (seen.push(n), n - 1));
    expect(seen).toEqual([4, 3, 2]);
  });
  it('入力を変更しない', () => {
    const src = [1, 2, 3];
    shuffle(src, () => 0);
    expect(src).toEqual([1, 2, 3]);
  });
  it('空と 1 件はそのまま', () => {
    expect(shuffle([], cryptoRandomInt)).toEqual([]);
    expect(shuffle(['x'], cryptoRandomInt)).toEqual(['x']);
  });
  it('3 件で 6 通りすべてが出て、偏りが小さい', () => {
    const count = new Map<string, number>();
    for (let i = 0; i < 6000; i++) {
      const k = shuffle(['a', 'b', 'c'], cryptoRandomInt).join('');
      count.set(k, (count.get(k) ?? 0) + 1);
    }
    expect(count.size).toBe(6);
    for (const n of count.values()) expect(n).toBeGreaterThan(800); // 期待値 1000
  });
});

describe('cryptoRandomInt', () => {
  it('0 以上 maxExclusive 未満の整数', () => {
    for (let i = 0; i < 2000; i++) {
      const v = cryptoRandomInt(7);
      expect(Number.isInteger(v) && v >= 0 && v < 7).toBe(true);
    }
  });
  it('不正な上限は RangeError', () => {
    expect(() => cryptoRandomInt(0)).toThrow(RangeError);
    expect(() => cryptoRandomInt(1.5)).toThrow(RangeError);
  });
});
```

### Task 3: 保存・書き出し・読み込み

**Files:**
- Create: `src/storage/store.ts`
- Test: `src/storage/store.test.ts`

**Interfaces:**
- Consumes: Task 2 の `Store` `NewId` `createInitialStore` `normalizeName` `GROUP_MEMBER_MAX`
- Produces:

```ts
export const STORAGE_KEY = 'chusen:v1';
export const BROKEN_KEY = 'chusen:v1:broken';
export type StorageLike = Pick<Storage, 'getItem' | 'setItem'>;
export type LoadNotice = 'none' | 'broken' | 'unavailable';

export function parseStore(value: unknown): Store | null;
export function loadStore(storage: StorageLike | null, newId: NewId): { store: Store; notice: LoadNotice };
export function saveStore(storage: StorageLike | null, store: Store): boolean; // 失敗・storage null は false、例外は投げない
export function exportStore(store: Store): string;       // JSON.stringify(store, null, 2)
export function importStore(text: string): Store | null; // JSON.parse 失敗も null
export function getBrowserStorage(): StorageLike | null; // localStorage に試し書きして不可なら null
```

- `parseStore` が `null` を返す条件: `version !== 1`／`groups` が配列でない・空／グループ ID 重複／`id` `name` が空でない文字列でない／`normalizeName(name) !== name`（未 trim・21 文字以上）／`active` `muted` が boolean でない／メンバー 31 人以上／同一グループ内でメンバー ID 重複
- `parseStore` は未知のプロパティを捨て、`lastGroupId` が存在しないグループを指す・`null` の場合は先頭グループの ID に直す
- `loadStore`: `storage === null` → 初期ストア + `'unavailable'`。キーなし → 初期ストア + `'none'`。JSON 不正または `parseStore` が `null` → 生の文字列を `BROKEN_KEY` に書いてから初期ストア + `'broken'`

- [ ] **Step 1: 失敗するテストを書く。** `Map` で作った偽 `StorageLike` を使い、最低限:
  - `saveStore` → `loadStore` の往復で同値、`notice: 'none'`
  - 保存値が `'{oops'` → `notice: 'broken'`、`BROKEN_KEY` に `'{oops'`、返るストアは初期状態
  - 保存値が `{"version":2,...}` → `'broken'`
  - `loadStore(null, id)` → `'unavailable'`、`saveStore(null, s)` → `false`
  - `setItem` が例外を投げる storage → `saveStore` は `false` を返し例外を投げない
  - `importStore(exportStore(s))` が `s` と同値
  - `importStore` が `null`: `'こんにちは'`、`'[]'`、`'{"version":1,"groups":[]}'`、名前 21 文字、名前が `' 佐藤'`、メンバー 31 人、グループ ID 重複、`active: 'yes'`
  - `parseStore` が未知プロパティ（`extra: 1`）を落とす／`lastGroupId: 'ない'` を先頭グループ ID に直す
- [ ] **Step 2: 失敗確認** → **Step 3: 実装** → **Step 4:** `npm test && npm run typecheck`

```ts
export const TIMELINE = {
  countdownEnd: 3, finalCornerStart: 19, finishStart: 23, finishEnd: 25.5, duration: 27,
} as const;
export type RaceEventKind =
  | 'slowStart' | 'rocketStart' | 'boost' | 'spin' | 'weave' | 'stall' | 'overtake' | 'finalComeback';
export type RaceEvent = { t: number; kind: RaceEventKind; racer: number }; // racer = 最終順位の添字（0 が 1 着）
export type Key = { t: number; p: number };                               // p: 0=スタート線, 1=ゴール線
export type Racer = { id: string; name: string; finishTime: number; keys: Key[] };
export type RaceScript = { racers: Racer[]; events: RaceEvent[] };        // racers は最終順位順
export function buildRaceScript(order: readonly { id: string; name: string }[], rand: Rand): RaceScript;
export function progressAt(racer: Racer, t: number): number;             // 線形補間。t<=3 は 0、finishTime 以降は 1
export function rankingAt(script: RaceScript, t: number): number[];      // 進行度の降順の racer 添字。同値は添字の小さい順

// commentary.ts
export type CommentaryKind = RaceEventKind | 'start' | 'finish';
export const TEMPLATES: Record<CommentaryKind, readonly string[]>;        // '{name}' を名前に置換
export type Cue = { t: number; text: string };
export function buildCommentary(script: RaceScript, rand: Rand): Cue[];
```

**台本の作り方（`buildRaceScript`）:**

1. ゴール時刻: `gap = min(0.6, 2.5 / (N - 1))`、`finishTime[i] = 23 + gap * i`
2. 最終コーナー入口（t=19）の順位 `cornerRank`（0 が先頭）を作る: 最終順位をシャッフルし、N≥3 では 1 着（添字 0）の `cornerRank` が `Math.ceil(N / 2)` 以上になるまで引き直す（N=3 なら最後尾）。N=2 では入れ替えない
3. t=19 の進行度: `p19 = 0.80 - 0.10 * cornerRank / (N - 1)`（先頭 0.80、最後尾 0.70）
4. イベントを決める: t≈3.3 に `slowStart` か `rocketStart` を 1 つ。5〜18 秒に 1.8 秒以上あけて 4〜6 個（`boost` `spin` `weave` `stall` `overtake` から、対象ロケットは偏らないよう選ぶ）。N≥3 なら t=20 に `finalComeback`（racer 0）
5. キー時刻は `[3, 7, 11, 15, 19]`。各区間の増分は `0.8〜1.2` の乱数重みを基本とし、その区間にイベントがあるロケットは `rocketStart/boost/overtake` で ×1.6、`slowStart/spin/stall` で ×0.4。重みを合計で割って `p19` を配分する（各増分は正なので単調）
6. 最後に `{ t: finishTime, p: 1 }` を足す。`finalComeback` の対象は t=21 に `p = p19 + (1 - p19) * 0.3` のキーを挟み、最終コーナー前半は溜めて後半で伸びるようにする

**実況（`buildCommentary`）:** t=0.5 に `start`（整列中の煽り）、全イベントに 1 本ずつ対応する文（時刻はイベントと同じ）、`racers[0].finishTime` に `finish`（1 着の名前）。文は種類ごとのテンプレートから `rand` で選ぶ。イベント時刻の取り方（3.3 秒、5.1〜18 秒で 1.8 秒間隔以上、20 秒、23 秒）により、キュー同士は必ず 1.5 秒以上あくので捨てる処理は不要。本数は `イベント数 + 2`（N≥3 で 8〜10 本、N=2 で 7〜9 本）。手順 4 の中盤イベントは 5.1 秒以降に置くこと。

- `TEMPLATES` は各種類 3 本以上・合計 30 本以上。`start` 以外は必ず `{name}` を含む。固定する文: `finish` の 1 本は `'ゴール！！ 栄光のトップバッターは {name}！'`。残りは実装者が自作（Global Constraints 参照）
